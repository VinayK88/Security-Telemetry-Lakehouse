## Data contracts

Every event carries:

- deterministic `event_id`
- `event_time`
- `ingest_time`
- tenant
- source
- event type
- entity identifiers
- action
- outcome
- risk/enrichment fields

The raw contract should be versioned.

## Correctness

### Delivery

Prefer at-least-once transport plus idempotent processing.

### Deduplication

Use event IDs generated by the source where possible. Otherwise derive IDs from immutable source fields.

### Event time

Never substitute arrival time for event time. Offline endpoints and batch collectors make that unreliable.

### Watermarks

A watermark bounds state and determines how late events affect aggregates.

### Replay

Raw events should remain replayable so feature and detection logic can be recomputed.

## Scalability

Horizontal scale should be driven by:

- partitions
- consumer concurrency
- state-store size
- sink throughput
- shuffle volume

Avoid a routing key that concentrates all traffic for a large tenant or principal into one partition.

## Observability

Track:

- ingress events/sec
- normalized events/sec
- malformed rate
- duplicate rate
- lag by partition
- late-event rate
- watermark delay
- state-store size
- sink latency
- p50/p95/p99 end-to-end latency
- cost per million events

## Data quality

Security analytics fail silently when field quality drifts. Add automated checks for:

- null rates
- enum drift
- timestamp skew
- cardinality explosions
- schema incompatibility
- source-specific volume anomalies
